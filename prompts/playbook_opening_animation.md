# 开场动画

## 描述

用户给一段视觉描述（logo 形态、氛围、色调、节奏感）和可选的参考图，agent 在画布上搭出这条开场动画：分镜规划 → 生成 → 可选配乐。每一步都是画布上的节点，用户在任意一批落盘之前可以改它。

与「剧情动画」的区别：开场动画通常没有需要跨段存活的角色，总时长落在单个模型的单段上限内，所以是一条节点、一次生成、段内切镜的短流程。

## 输入参数

| 参数 | 必填 | 缺省行为 |
|---|---|---|
| 视觉描述 | 是 | 没有就追问，不要自己编。logo 形态、氛围、色调、节奏感都算 |
| 总时长 | 是 | 用户没说就问，不猜。这个数字决定运镜密度 |
| 模式 | 否 | 用户没说 → 默认多机位分镜；一镜到底要用户明确要 |
| logo / 品牌参考图 | 否 | 有 → 建 image 节点承载，连到 video 节点；文字只写差异 |
| 氛围、画风、模型 | 否 | 不追问，用默认；用户提了才采纳 |
| 运镜强度 | 否 | 用户没说 → standard（标准）。restrained（克制）/ standard（标准）/ flashy（炫技）决定允许哪些手法，不决定镜头数 |
| 配乐 | 否 | 用户没提 → 不生成音乐，交付时说明音频需用户在外部配 |

参考图和文字是分工的，不是重复的：有参考图时文字只写差异，不重述图里已有的细节。

## 时长与形态

这个技能只有一种形态：一个 video 节点，段内切镜。

| 模型 | 单段上限 | 下限 |
|---|---|---|
| seedance-2.0 | 15 秒 | 4 秒 |
| hailuo-h3 | 15 秒 | 5 秒 |

规则，按顺序：

1. 用户提的总时长不超过单段上限 → 一个节点
2. 超过 → 不拆段。告诉用户这个技能的上限，要么压到上限内，要么改用「剧情动画」走分段
3. 用户提的单段时长超过上限 → 先在上下文的 availableModels 里找支持该时长的模型换掉；换不了才告诉用户会被压
4. 时长被压时节点上会留下 agentParamClamped 记录。读到它必须告诉用户实际时长变了，不要自己吞掉

第 2 条是与「剧情动画」的分界：这个技能刻意不支持分段，因为开场动画的价值在一次性冲击，不在叙事推进。

## 执行逻辑

### 步骤 1 · 分镜规划

产物：一个 video 节点。prompt 里写全部分镜（`分镜N丨节拍丨时间段丨镜头设计：动作`，时间段首尾相接，总长等于该条时长）。

没有角色锚点这一步。开场动画的主体通常是 logo、字形、光效、空间，不跨段存活，不需要锚点。用户明确给了角色（比如吉祥物）时，才先建锚点 generator、先审先出图，再回来做这一步。

运镜强度是 cameraIntensity：restrained（克制）/ standard（标准，默认）/ flashy（炫技）。它决定允许哪些手法，不决定镜头数。用户没说就用 standard。

停点：prompt 出来后等用户审，审到分镜级。

### 步骤 2 · 生成

一个 video 节点，批准即成片。

停点：跑完报实际时长；若 agentParamClamped 在场，先说时长变了，再说别的。

交付视频。配乐、音效由用户在画布外完成，交付时说明这一点。

## 核心原则

### 原则 1 · 停点是结构，不是礼貌

每阶段的停点靠按批批准实现：agent 建节点 → 用户审 → 批准 → 才跑。不需要判断「我是不是该问一下」，闸门本来就在。所以只说在哪一批之后停、等什么审。

### 原则 2 · 时长是用户给的，不是估的

总时长是用户给的，不是估的——估错一次整条重跑，用户没说就问。但镜头节奏由运镜强度决定，不由时长决定。同样 10 秒，克制档出长镜，炫技档出快切，这是对的。

### 原则 3 · 多机位在段内切镜，不在节点间切

一个节点是一条完整的开场动画，不是一个镜头。分镜级编辑便宜，执行贵：改一个分镜等于重跑整条。所以用户说「改分镜2」时，先报「这要重跑整条，约 X 秒」，等用户确认再改。

### 原则 4 · 参考图承载细节，文字只写差异

有 logo 参考图时，文字不超过 20 字概括，不重述图里已有的形态细节。理由不是省事，是一致性：两次重述会有出入，而出入就是镜头之间的不一致。

### 原则 5 · 结构化字段只在用户点名时才填

参考图、模型这些走结构化字段的东西，只有用户在消息里用 @ 点名了才填。没点名就留空，让执行层的默认接管。

判据是消息里的 @ 记号，不是措辞。用户写「那张图」「用 图片模型」不算点名——那是拿措辞猜意图，和执行层不能替你猜是同一件事。

模型自主挑的后果是用户看不见：提案里写了 图片模型，落地就把默认的 nano 盖掉；连了一条用户没要求的参考图，prompt 里就多出「参考 角色参考1」。这两次都不是用户要的，但都悄悄生效了。

用户没点名而你判断需要参考图时，问一句，让用户 @。

参数表里的「用户提供角色参考图」措辞不动，原则里已经定义了"提供"的判据。

### 原则 6 · 不含台词

画布上没有配音节点，没有测语音时长的字段，默认的海螺模型不带音频开关。所以带台词的视频在画布上无法执行。

用户给了台词 → 转成字幕建议，不要写进 video prompt，也不要填 fidelity。fidelity 一旦填上，保真检查会要求逐字一致和测过的语音时长，两个条件在画布上都满足不了，视频直接失败。strict 设成 false 能绕过检查，但同时把台词逐字校验一起关掉，不是出路。

音频放在外部：用户在画布外配音、配乐，再和成片合成。交付时说明这一点。

## 输出模板

```
【参考图】（image 节点，承载 logo / 品牌图）
[logo]：{@图1} 不超过20字概括

【分镜提示词】（一个 video 节点，duration = 总时长）
分镜1丨[节拍]丨0-Xs丨[景别+角度+主运镜]：[动作]
分镜2丨[节拍]丨X-Ys丨[景别+角度+主运镜]：[动作]

【配乐】（music 节点，仅在用户要时；时长 = 成片实际长度）
[风格 / 情绪 / 乐器 / 时长]

改分镜2 = 只动那一行，但重跑整条。
```

## 使用示例

（流程层技能的示例是「停点长什么样」，不是「输出长什么样」。）

- **示例 A · 常规**：用户说「10 秒，深色科技风，logo 从粒子聚拢成形」。agent 建 image 节点承载 logo，出一个 video 节点，段内切 0-3／3-7／7-10 三镜。停点：用户看到完整 prompt，能改分镜级那一行，也能改整条。批准后才生成。跑完报实际 10 秒。
- **示例 B · 时长超限**：用户说「30 秒开场」。agent 不拆段，告诉用户这个技能上限 15 秒，要么压到 15 秒，要么改用「剧情动画」走分段。
- **示例 C · 有角色**：用户说「吉祥物从画外跑进来按按钮」。agent 先建角色锚点 generator、审图出图，之后才建 video 节点。这是唯一出现锚点停点的情况。
