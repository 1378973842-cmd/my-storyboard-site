# 开场动画

## 描述

用户给一段视觉描述（logo 形态、氛围、色调、节奏感）和可选的参考图，agent 在画布上搭出这条开场动画：分镜规划 → 生成 → 可选配乐。每一步都是画布上的节点，用户在任意一批落盘之前可以改它。

与「剧情动画」的区别：开场动画通常没有需要跨段存活的角色，总时长落在单个模型的单段上限内，所以是一条节点、一次生成、段内切镜的短流程。

## 输入参数

| 参数 | 必填 | 缺省行为 |
|---|---|---|
| 故事 / 视觉描述 | 是 | 没有就追问，不要自己编。一段小剧情和视觉描述都算——用户会给「10 秒，诸葛亮在帐中，结尾切到界面」这种故事，也会给「logo 从粒子聚拢」这种纯视觉描述。结尾怎么收他会在故事里写清，不用追问参考图。 |
| 总时长 | 是 | 用户没说就问，不猜。这个数字决定运镜密度 |
| 模式 | 否 | 见步骤 1 |
| logo / 品牌参考图 | 否 | 有 → 建 image 节点承载，连到 video 节点。传了图像部件才只写差异；只有地址就按故事写全 |
| 氛围、画风、模型 | 否 | 不追问，用默认；用户提了才采纳 |
| 运镜强度 | 否 | 见步骤 1 |
| 配乐 | 否 | 用户没提 → 不生成音乐，交付时说明音频需用户在外部配 |

参考图和文字是分工的，不是重复的：传了图像部件时，文字只写差异，不重述图里已有的。只有地址、没有图像部件时这条不适用，按故事写全。

## 时长与形态

这个技能只有一种形态：一个 video 节点，段内切镜。

| 模型 | 单段上限 | 下限 |
|---|---|---|
| seedance-2.0 | 15 秒 | 4 秒 |
| hailuo-h3 | 15 秒 | 5 秒 |

规则，按顺序：

1. 用户提的总时长不超过单段上限 → 一个节点
2. 超过 → 不拆段。告诉用户这个技能的上限，要么压到上限内，要么改用「剧情动画」走分段
3. 用户提的单段时长超过上限 → 先在上下文的 availableModels 里找支持该时长的模型换掉；换不了才告诉用户会被压
4. 时长被压时节点上会留下 agentParamClamped 记录。读到它必须告诉用户实际时长变了，不要自己吞掉

第 2 条是与「剧情动画」的分界：这个技能刻意不支持分段，因为开场动画的价值在一次性冲击，不在叙事推进。

## 执行逻辑

### 步骤 0 · 资产分析（有参考图时做）

这一步的产物不是『识别这是什么图』。只说图里是阿波罗、是神殿，等于没做这一步——那是识别，不是分析。这一步只报两样：图里没有而故事需要的；图里有而和故事冲突的。两样都没有时，一行说『图与故事一致』。报完停下等用户确认，确认前不写任何分镜、不建任何节点。

先看这张图是不是以图像部件传进来的。地址字符串不是图。

- 传了图像部件：读图。读的不是罗列图里有什么，而是判断两件事——图里已有的哪些和故事冲突，故事要的哪些图里没有。冲突和缺失写进分析结果；图里已有、且和故事不冲突的，不要重述
- 没传图像部件：明说「这张图我看不到内容，只能按故事描述写」。不要推断发型、盔甲、脸色，再当成从图里读到的

产物：传了图时，一条「冲突与缺失」，不附带一份图里细节清单；没传图时，先写看不到，再按故事写全。
这一步不出节点，只出分析结果，写在停点里给用户看。

停点：报出冲突、要补的，以及哪张图没传到。等用户确认再继续。

你说不出任何卡。提问卡、审批卡都是系统在你调用对应工具时附上的。
正文里写「请在下方卡片选择」「请批准」这类话，用户看不到任何卡——
卡不是文字画出来的，是工具调用触发的。
要让用户看到卡片，就调那个工具；不调，就别在正文里假装它存在。

每个停点报出你为什么停在这儿、下一步为什么必须先做这件事。
只说做了什么，用户没法判断你停得对不对。

发现素材之间有冲突（画风、时代、材质、比例），
生成前如实提醒，不要等用户发现。
你看得见而用户看不见的不一致，是你的责任不是他的。

### 步骤 1 · 分镜规划

开工前先确认两件事用户答没答：多机位还是一镜到底、运镜克制/标准/炫技。没答就不能建节点、不能写分镜——先问，等回答。这两项和时长一样是开工前提，不是可以顺便套用的默认。这些要用户回答的问题用 ask_user 卡片发出，一张卡一个问题，顺序不变。不要把问题写进对话正文。每张卡的可点项是 type text，并带一个 type input 让用户自己写。用户点忽略时答案是「用默认」，这题算答过，按默认继续，不要再问。

问风格时不要问抽象档位，问具体参照：有没有喜欢的技能/镜头参考？（某款游戏的元素爆发、某部动漫的招式、某电影的某一幕）用具体案例引导，不要问『您想要什么风格』。用户给了参照物，你就有了具体词汇、具体节奏、具体色彩；只拿到档位值，你只能复述参数。主动提出 1-2 个建议方案，说明将要呈现的效果，让用户判断方向对不对。

建 video 节点和连它的参考图，必须在同一个提案里做完。
不要先建一个不带边的 video、下一拍再补边——
补边会迫使 prompt 重写一遍，而中间那一拍的 video 是不能用的。

「已生效清单」是防重复的约束，不是进度报告。
清单里已经有这颗节点时，不要再新建同一条——
要么更新那颗已有的，要么问用户要改什么。
只有用户明确说要「再来一条」「新建一个版本」时才新建，
并在 summary 里说明和已有那颗的差别。

克制不等于一镜到底，一镜到底也不等于克制。
克制档 + 多机位 = 切几镜，每镜都是长镜缓慢推进；
克制档 + 一镜到底 = 一整镜，全程一个主运镜。

短句肯定（好的、确认、行、继续、嗯）看的是有没有审批卡在等批准，不是有没有提案——建节点、连线、改参数提案后直接落板，不会停在待确认。没有审批卡时，它不触发任何新建，也不触发运行——先问用户要做什么。有审批卡时，它也不等于批准——批准只能在卡上点。

用户可能在卡之外直接打字『确认』『好的』。
这种短句不构成批准，也不触发新建——批准只在审批卡上点。

video 的 prompt 里不要写参考图的文件名、节点名或任何 id。参考关系只靠连线表达，prompt 只写画面本身。文件名对视频模型是噪音，而『参考 xxx』这句话它读不懂也不会执行。

### 分镜行怎么写

四栏结构不动：分镜N丨节拍丨时间段丨镜头设计

最后一栏写成一整段自然语言，不要再往里加 丨。
校验器靠 丨 切栏，栏里再出现 丨 会把一段话切成两栏。

这一栏要写足的九类，按镜头类型挑重点，不要求每镜写全：

- 表情与眼神：什么情绪、眼神焦点在哪、有没有对视
- 身体状态：呼吸、肌肉紧绷、姿态重心
- 位置与构图：主体在画面哪（三分线/居中/边缘）、前中后景层次、
  多人时的前后左右与遮挡
- 动作精度：起止状态——从 A 到 B，不是"做 A"。力从哪来、传到哪
- 特效：形态、颜色、怎么生成、怎么运动、怎么消散
- 道具与环境交互：接触反馈——脚踏雪凹陷、手触石溅屑、袍角被风掀
- 物理附着：衣物、头发、披风因风或重力怎么动
- 光：方向、色温、硬度、变化
- 视线与关系：谁看谁、看向画外还是画内

按镜头类型选重点：
- 远景 / 建立：构图、环境光、物理附着、主体在画面哪。表情和道具细节可省
- 特写：表情、眼神、材质、光的方向。构图和环境可省
- 动作镜：起止、力传导、接触反馈、物理附着。环境描述可省
- 特效镜：形态、颜色、生成与消散、光的变化。表情可省
- 对白 / 静场：表情、视线、呼吸、重心。动作精度可省

每镜挑该类型的重点写足，其余一句带过或不写。
全维度套一遍会让提示词变长不变好，还会稀释真正重要的那几样。

四层的篇幅配比：风格质量声明 10%、运镜系统 15%、核心画面 60%、技术细节 15%。大头必须在核心画面层——动作怎么发生、光怎么变、特效怎么生灭。风格和细节两层是收尾，不是主体。

例：
分镜1丨神降丨0-3s丨大远景仰拍，镜头从云层外快速推进。
阿波罗从画面右上方的裂云俯冲而下，占画面三分之一，
身后金色光翼完全展开，翼尖拖出两道正在消散的光屑。
白袍被下坠的气流向上掀起，袍角翻卷。
云层被他撞开，裂口边缘泛出金光。
远景里他的脸只是一个小亮点，看不清表情，但下颌朝下对准神殿。

远景那一镜里，外观锚定和构图合并写，不要单独再抄一遍脸和服装。

要提到参考图时写它的语义角色（阿波罗的面部、神殿的结构），不要写『参考图1』这种编号——编号对视频模型无意义，引用关系靠连线顺序表达。

用户答『一镜到底』时，不要写分镜1/分镜2/分镜3——那是一个连续镜头。
写成一段，格式是：
一镜到底丨[节拍]丨0-[总时长]s丨[一整段连续镜头正文]
同一时段只有一个主运镜。要在时间轴上换运镜，写成
「0-3s 缓慢推进，3-6s 转为轻横移」这样的节点标注，
不要拆成两镜。
时间段那一栏只写总长，因为不切镜就没有多段。
首尾相接那条规则在一镜到底下不适用——它管的是多镜。

prompt 正文用创作稿的语言写。创作稿是中文就写中文，是英文就写英文。不要跟用户消息的语言走——用户消息在 16 条窗口里，会被挤出，挤出的那一轮你就看不见该跟谁走了，于是自己挑一种语言。创作稿在 draft.md 里，它不会被挤出。
词典里的「英文参考」那一列是帮你理解手法的，不要把英文写进 prompt。

引用只能作为附加信息出现——括号里、逗号后、或句末。
不要把记号放进句子主干（主语、宾语，或「由…建立的」这类结构）。
放进主干，胶囊一画就成了病句：
「由 神殿参考 建立的金色云层」——读不通，而且它把引用变成了画面内容。
正确写法：金色与粉色云层（参考 {{神殿图}}）在背景中铺开。

产物：一个 video 节点。prompt 里写全部分镜（`分镜N丨节拍丨时间段丨镜头设计：动作`，时间段首尾相接，总长等于该条时长。所有分镜的时间加起来等于节点时长，不是每个分镜等于节点时长）。

没有角色锚点这一步。开场动画的主体通常是 logo、字形、光效、空间，不跨段存活，不需要锚点。用户明确给了角色（比如吉祥物）时，才先建锚点 generator、先审先出图，再回来做这一步。

用户提出任何分镜级修改时，你的第一句回复必须是重跑成本（这要重跑整条，约 X 秒），不能先问改什么内容。报价在前，问需求在后。

用户要求加台词、旁白、对白时，不要写进 video prompt。转成字幕建议，并说明配音在画布外完成。台词进了 prompt 模型会当台词念，而画布没有配音节点。

停点：prompt 出来后等用户审，审到分镜级。

### 步骤 2 · 生成

「用户认可 prompt（符合预期、可以、就这样、没问题）之后，
下一拍直接提交运行——这颗 video 建好时已经自动落板，
提案里只写执行它的动作，不用再等一拍落板，也不要再建一颗。
不要只回一份进度报告就停在那儿等用户再说一遍。
审批卡是系统在你提交运行动作时附上的，你自己写不出来；
你不交运行提案，用户就看不到批准按钮，流程就卡在这一拍。」

一个 video 节点，批准即成片。

停点：跑完报实际时长；若 agentParamClamped 在场，先说时长变了，再说别的。

交付视频。配乐、音效由用户在画布外完成，交付时说明这一点。

## 核心原则

### 原则 1 · 停点是结构，不是礼貌

每阶段的停点靠按批批准实现：agent 建节点 → 用户审 → 批准 → 才跑。不需要判断「我是不是该问一下」，闸门本来就在。所以只说在哪一批之后停、等什么审。

### 原则 2 · 时长是用户给的，不是估的

总时长是用户给的，不是估的——估错一次整条重跑，用户没说就问。但镜头节奏由运镜强度决定，不由时长决定。同样 10 秒，克制档出长镜，炫技档出快切，这是对的。

### 原则 3 · 多机位在段内切镜，不在节点间切

一个节点是一条完整的开场动画，不是一个镜头。分镜级编辑便宜，执行贵：改一个分镜等于重跑整条。所以用户说「改分镜2」时，先报「这要重跑整条，约 X 秒」，等用户确认再改。

### 原则 4 · 参考图承载细节，文字只写差异

有 logo 参考图时，文字不超过 20 字概括，不重述图里已有的形态细节。理由不是省事，是一致性：两次重述会有出入，而出入就是镜头之间的不一致。

只写差异管的是不重述图里已有的；反过来，图里没有而故事需要的必须补上。两句合起来才是完整的参考图用法——只删不补会让角色缺道具，只补不删会重述出出入。

不重述图里已有的细节，前提是这张图以图像部件传进来了。只有地址、没有图像部件时这条不适用——按故事写全描述，不要为了「只写差异」而省掉你其实并不知道图里有没有的细节。

不重述图里已有的细节，管的是不要把图里看得见的东西再抄一遍。它不等于角色只写名字。角色在 prompt 里仍要有一个可识别的外观锚定（脸、身材、服装里最显著的那么一两样），否则视频模型收到一个名字加一张图，不知道该保的是脸、身材还是服装。判断标准：图里有的、且这一镜会看清的 → 不抄；图里有的、但这一镜是远景或剪影 → 仍要写，因为那一镜里图帮不上。

### 原则 5 · 结构化字段只在用户点名时才填

参考图、模型这些走结构化字段的东西，只有用户在消息里用 @ 点名了才填。没点名就留空，让执行层的默认接管。

判据是消息里的 @ 记号，不是措辞。用户写「那张图」「用 图片模型」不算点名——那是拿措辞猜意图，和执行层不能替你猜是同一件事。

模型自主挑的后果是用户看不见：提案里写了 图片模型，落地就把默认的 nano 盖掉；连了一条用户没要求的参考图，prompt 里就多出「参考 角色参考1」。这两次都不是用户要的，但都悄悄生效了。

用户没点名而你判断需要参考图时，问一句，让用户 @。

参数表里的「用户提供角色参考图」措辞不动，原则里已经定义了"提供"的判据。

### 原则 6 · 不含台词

画布上没有配音节点，没有测语音时长的字段，默认的海螺模型不带音频开关。所以带台词的视频在画布上无法执行。

用户给了台词 → 转成字幕建议，不要写进 video prompt，也不要填 fidelity。fidelity 一旦填上，保真检查会要求逐字一致和测过的语音时长，两个条件在画布上都满足不了，视频直接失败。strict 设成 false 能绕过检查，但同时把台词逐字校验一起关掉，不是出路。

音频放在外部：用户在画布外配音、配乐，再和成片合成。交付时说明这一点。

## 内容不满意时怎么改

用户说不满意时，先判断是哪一类问题，不要整段重写：

| 症状 | 改法 |
|---|---|
| 特效不够强 | 增加冲击帧密度、强化震屏描述 |
| 节奏拖沓 | 压缩蓄力段、增加爆发段跳切 |
| 画面暗淡 | 风格层加高对比度光影、强化发光粒子 |
| 角色变形 | 核心画面层加外观锁定描述（发色、服装、标志性道具始终保持） |

报出你判断的是哪一类、要改哪一层，再改。

## 输出模板

```
【参考图】（image 节点，承载 logo / 品牌图。不要写进 video 的 prompt）
[logo]：{@图1} 传了图像部件才不超过20字概括；没传到就按故事写全

【分镜提示词】（一个 video 节点，duration = 总时长）
分镜1丨[节拍]丨0-Xs丨[景别+角度+主运镜]：[动作]
分镜2丨[节拍]丨X-Ys丨[景别+角度+主运镜]：[动作]

【配乐】（music 节点，仅在用户要时；时长 = 成片实际长度）
[风格 / 情绪 / 乐器 / 时长]

改分镜2 = 只动那一行，但重跑整条。
```

## 使用示例

（流程层技能的示例是「停点长什么样」，不是「输出长什么样」。）

- **示例 A · 常规**：用户说「10 秒，深色科技风，logo 从粒子聚拢成形」。agent 建 image 节点承载 logo，出一个 video 节点，段内切 0-3／3-7／7-10 三镜。停点：用户看到完整 prompt，能改分镜级那一行，也能改整条。批准后才生成。跑完报实际 10 秒。
- **示例 B · 时长超限**：用户说「30 秒开场」。agent 不拆段，告诉用户这个技能上限 15 秒，要么压到 15 秒，要么改用「剧情动画」走分段。
- **示例 C · 有角色**：用户说「吉祥物从画外跑进来按按钮」。agent 先建角色锚点 generator、审图出图，之后才建 video 节点。这是唯一出现锚点停点的情况。
