# 开场动画 · 参数与时长（知识层）

## 输入参数

| 参数 | 必填 | 缺省行为 |
|---|---|---|
| 故事 / 视觉描述 | 是 | 没有就追问，不要自己编。一段小剧情和视觉描述都算——用户会给「10 秒，诸葛亮在帐中，结尾切到界面」这种故事，也会给「logo 从粒子聚拢」这种纯视觉描述。结尾怎么收他会在故事里写清，不用追问参考图。 |
| 总时长 | 是 | 用户没说就问，不猜。这个数字决定运镜密度 |
| 模式 | 否 | 见步骤 1 |
| logo / 品牌参考图 | 否 | 有 → 建 image 节点承载，连到 video 节点。传了图像部件才只写差异；只有地址就按故事写全 |
| 氛围、画风、模型 | 否 | 不追问，用默认；用户提了才采纳 |
| 运镜强度 | 否 | 见步骤 1 |
| 配乐 | 否 | 用户没提 → 不生成音乐，交付时说明音频需用户在外部配 |

参考图和文字是分工的，不是重复的：传了图像部件时，文字只写差异，不重述图里已有的。只有地址、没有图像部件时这条不适用，按故事写全。

## 时长与形态

这个技能只有一种形态：一个 video 节点，段内切镜。

| 模型 | 单段上限 | 下限 |
|---|---|---|
| seedance-2.0 | 15 秒 | 4 秒 |
| hailuo-h3 | 15 秒 | 5 秒 |

规则，按顺序：

1. 用户提的总时长不超过单段上限 → 一个节点
2. 超过 → 不拆段。告诉用户这个技能的上限，要么压到上限内，要么改用「剧情动画」走分段
3. 用户提的单段时长超过上限 → 先在上下文的 availableModels 里找支持该时长的模型换掉；换不了才告诉用户会被压
4. 时长被压时节点上会留下 agentParamClamped 记录。读到它必须告诉用户实际时长变了，不要自己吞掉

第 2 条是与「剧情动画」的分界：这个技能刻意不支持分段，因为开场动画的价值在一次性冲击，不在叙事推进。
